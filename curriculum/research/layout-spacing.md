# Layout and Spacing Systems for Sales Websites

## Sources

- https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content-discovered/ — Original 232-user eyetracking study establishing the F-shaped scanning pattern for text-heavy pages; reconfirmed by an 11-year NN/g follow-up.
- https://www.nngroup.com/articles/scrolling-and-attention-original-research/ — NN/g's own scrolling-attention data: 2018 study found 57% of viewing time above the fold / 74% in the first two screenfuls, revised down from the often-misquoted 80% (2010 study).
- https://www.nngroup.com/articles/gestalt-proximity/ — Proximity principle: spacing alone (no borders/color) signals grouping; warns that careless proximity can camouflage important controls or hide them from task-focused users.

## Rules

1. Use 8px as the base spacing unit; all section margins, paddings, and gutters should be multiples of 8 (8, 16, 24, 32, 40, 48, 64, 80, 96px). [LAW] — Medium/MacTavish, Prototypr
2. Reserve the 4px sub-grid exclusively for internal component spacing where 8px is too coarse (icon-to-label gap, button internal padding, inline badge spacing) — never for section-level layout. [LAW] — Medium/MacTavish, Prototypr
3. Build the spacing scale as a fixed token set, not arbitrary values: a typical working scale is 4/8/12/16/24/32/48/64/96/128px (7–10 steps). [LAW] — Figma (analogous to its 7–12 type-size guidance), Prototypr
4. Set line-height values as multiples of 4px so text baselines stay locked to the 8pt grid (vertical rhythm). [LAW] — Figma
5. The 8pt/4pt dual grid exists because it scales without fractional pixel values across 1×, 1.5×, 2×, and 3× display densities — a practical reason to keep to it on any site serving both desktop and mobile. [LAW] — Prototypr
6. Minimum touch/click target size: 44×44pt (Apple HIG) or 48×48dp (Material Design); use 44px as the CSS floor on any web target since WCAG 2.5.5 (AAA) also specifies 44×44 CSS px. [LAW] — LogRocket, Apple HIG, m1.material.io
7. Leave at least 8px of clear space between adjacent tappable targets (buttons, nav links, icon buttons) to prevent mis-taps, even when each target individually meets the 44/48px minimum. [LAW] — m1.material.io
8. Spacing between items inside a group must be visibly smaller than spacing between groups — as a working ratio, keep inter-group spacing at roughly 2× (or more) of intra-group spacing so grouping reads without borders or background color. [LAW] — NN/g Gestalt Proximity, Smashing Magazine
9. Reduce the whitespace between a value-proposition headline/copy block and its CTA button relative to surrounding whitespace; this measurably raises click-through by framing copy+CTA as one decision unit. [LAW] — Smashing Magazine (A/B-tested)
10. Audit every responsive breakpoint for broken proximity: elements that read as grouped at desktop width can drift apart (or collide with unrelated elements) at mobile width if spacing isn't re-verified per breakpoint. [LAW] — NN/g Gestalt Proximity
11. Body text column width should sit at 45–75 characters per line, with ~66 characters as the target optimum. [LAW] — Baymard, Bringhurst (via Baymard/UXPin)
12. Never exceed 80 characters per line for Latin-script body text — this is the WCAG-referenced hard ceiling, not just a readability nicety. [LAW] — WCAG (via Baymard/UXPin sourcing)
13. On text-dense pages (blog-style, comparison tables, long-form product descriptions), front-load the highest-value words into the first two words of headers, bullets, and the opening two paragraphs — this is where F-pattern scanning concentrates attention. [LAW] — NN/g F-Shaped Pattern (232 users, reconfirmed 11 years later)
14. For sparse, single-offer conversion pages (hero + one CTA), lay elements on a Z-path: logo top-left, nav/secondary CTA top-right, hero visual diagonal-center, primary CTA bottom-right — this fits low-text pages better than the F-pattern, which only emerges under text density. [MIXED] — industry synthesis (Instapage/Wordstream/99designs), not a direct NN/g eyetracking finding — treat as a design heuristic, not a measured law
15. Render the core value proposition, a supporting visual, and the primary CTA inside the first viewport with zero scrolling required — 57% of page-viewing time and 74% of attention concentrate in the first two screenfuls. [LAW] — NN/g Scrolling and Attention (2018 update; supersedes the older, frequently misquoted 80% figure from 2010)
16. Design for a ~3-second stay-or-leave decision window before any scroll occurs: headline, product/value visual, and primary action must be legible at a glance, not discovered. [MIXED] — ConvertCart, consistent with NN/g's above-the-fold attention data
17. Budget 6–9 total sections for a full high-converting landing/product page; simple single-purpose tools can convert acceptably with 4–5. [MIXED] — ConvertCart (industry benchmark, not a controlled study)
18. Cap visual hierarchy at 3 contrast levels (combinations of size/weight/color contrast) per page or section — beyond 3 tiers, nothing reads as more important than anything else. [LAW] — MasterClass
19. Drive hierarchy primarily through size and contrast in value/saturation against the background, not through hue alone — hue differences alone are a weak and often inaccessible hierarchy signal. [LAW] — MasterClass
20. Set container max-width in the 1140–1320px range for the primary content column on desktop; 1200–1280px is the converged 2026 recommendation for generous-whitespace, premium-feel layouts. [MIXED] — Bootstrap convention via Framer Blog
21. Use mobile-first breakpoints and layer up: base styles unstyled/stacked for narrow viewports, then add multi-column/grid treatments at larger breakpoints — do not design desktop-first and squeeze down. [LAW] — Framer Blog (2026 responsive methodology)
22. Use `clamp()` for fluid type and spacing scaling between breakpoints instead of discrete jumps at fixed pixel values — this is the 2026-standard technique for avoiding layout "steps." [TREND-2026] — Framer Blog
23. Adopt container queries for component-level responsive spacing (e.g., a pricing card that reflows based on its own column width, not the viewport) — container queries reached Baseline support (~93% of global browser usage) and now play a larger role than viewport media queries for component-driven layouts. [TREND-2026] — LogRocket "Container queries in 2026"
24. Keep touch targets at the 44/48px floor even inside dense modular (bento) grid tiles — compressing a grid must never compress a tap target below the accessibility minimum. [LAW] — extension of Rule 6, m1.material.io
25. Total order cost (shipping, tax, fees) must be visible before or at the very start of checkout on any sales/commerce flow — unexpected costs drive roughly 48% of cart abandonment. [LAW] — Baymard Institute (checkout usability research)
26. Show a progress indicator on any multi-step checkout or multi-step signup flow — Baymard's usability testing consistently finds this reduces abandonment versus an unmarked step sequence. [LAW] — Baymard Institute
27. Place express/wallet payment buttons (Apple Pay, Google Pay, Shop Pay) above the fold in the purchase flow, not buried after a full form — sites adding Apple Pay saw an average 22.3% conversion increase in the cited analysis. [MIXED] — single-source figure via Baymard-adjacent reporting; verify against your own funnel before treating as guaranteed
28. Treat "5+ reviews" as a product-page threshold worth engineering the layout around (visible star rating + count near the buy box) — 5+ reviews correlates with substantially higher purchase likelihood, with the effect reported as larger for $100+ items. [MIXED] — Noun Project Blog, single-source correlational claim, not causally isolated
29. Do not repeat the specific "+47% dwell time / +38% click-through" bento-grid statistics in client-facing or curriculum material — the originating article carries no methodology, sample size, or citation; use only the qualitative, verifiable claim that modular/bento layouts are a real 2024–2026 aesthetic trend adopted by Apple and Notion. [flag — see Open Questions]
30. Avoid scroll-jacking, hero-section heavy WebGL, and experimental/non-standard primary navigation on a sales page — these are documented award-circuit favorites that correlate with confused visitors and mobile failures, regardless of their design-award performance. [LAW] — wearetenet (citing Awwwards' own 40% Design / 20% Creativity / 10% Content judging weights as the structural reason award-winners skew away from usability)
31. Do not use "featured on Awwwards/FWA/CSSDA" or award-site aesthetics as a proxy for conversion quality when designing a sales page — the awards explicitly under-weight content and usability, so award-winning patterns need independent conversion validation before reuse. [LAW] — wearetenet

## Trends 2024-2026

- **Bento grid layouts** — Asymmetric, modular card grids (named for Japanese lunch boxes) became the dominant marketing-site compositional pattern 2024–2025, popularized by Apple and Notion. By mid-2026 the pattern shows clear overuse fatigue and a "brutalist/anti-grid" counter-trend has emerged (deliberately broken layouts, raw HTML aesthetics, monospace type) as a direct reaction. **Shelf life: peaked, now fragmenting** — expect bento to persist as one option among several rather than the default, with an "active/agentic bento" variant (hover-expand tiles, dynamic content) as its most likely durable descendant. Use selectively and intentionally, not as a default template.
- **Container queries replacing viewport media queries for components** — Reached Baseline browser support around 2023 and by 2026 are the preferred tool for component-level (not page-level) responsive spacing. **Shelf life: durable** — this is a platform capability shift, not a stylistic trend, and will keep growing in adoption for years.
- **`clamp()`-driven fluid spacing/typography** — Replacing fixed breakpoint jumps with continuous scaling. **Shelf life: durable** — standard CSS technique, not a fad.
- **Whitespace-as-luxury-signal for premium positioning** — Continued and intensifying use of large whitespace ratios by premium/DTC brands (Apple, Chanel-style ecommerce). **Shelf life: durable** — this pattern has held for over a decade and is closer to a design law than a fleeting trend, though exact whitespace percentage remains undefined by any rigorous study.
- **Brutalist/anti-grid counter-movement** — Direct 2026 backlash to bento-grid ubiquity: intentionally raw, asymmetric, "ungridded" layouts. **Shelf life: uncertain, likely niche** — well-suited to portfolio/creative-agency sites, high-risk for mainstream sales pages where scannability and trust cues matter more than novelty.

## Anti-patterns

- **Award-circuit visual gimmicks on sales pages**: scroll-jacking, heavy WebGL hero animation, and experimental/non-standard primary navigation. These win Awwwards/FWA-style recognition (judged 40% Design + 20% Creativity, only 10% Content) but are documented to confuse visitors, fail on mobile, and drop conversions — because "looks good in a static screenshot" is a different bar than "completes the task in a real browser on a real connection." Source: wearetenet.
- **Copying award-winning aesthetics wholesale**: the aesthetic-usability effect makes a beautiful interface feel usable even when it isn't, which is precisely why award judges (and observers) miss the friction that hurts real conversion. Treat any award-site pattern as unvalidated until tested on your own funnel.
- **Citing unsourced bento-grid conversion stats**: "+47% dwell time, +38% CTR" traces to a design blog with no study, sample size, or methodology behind it (verified by direct source fetch). Repeating these numbers in client decks or curriculum material as if they were research findings is a credibility risk — use the qualitative trend claim only.
- **Breaking Gestalt proximity across breakpoints**: a spacing relationship that correctly groups a label with its form field, or a value prop with its CTA, at desktop width can silently drift apart (or collide with an unrelated element) when the layout reflows at mobile width. Every breakpoint needs its own proximity check, not just its own column count.
- **Cramming unrelated elements into false proximity**: proximity is powerful enough to camouflage important controls — e.g., burying a critical "Add" button among visually adjacent but functionally unrelated buttons (Next/Save/Cancel), or placing a real navigation element far from related content so it goes unnoticed (documented Kayak and Hulu examples in NN/g's proximity research). Don't let a tidy grid override the logical grouping of actions.
- **Sub-44px tap targets inside dense modular grids**: bento/card layouts that shrink each tile's interactive elements to fit more tiles above the fold routinely violate the 44/48px accessibility floor — information density must never be purchased at the cost of tap accuracy.
- **Treating "above the fold" as an exact, fixed pixel line**: the fold is a fuzzy attention gradient (57% of viewing time, 74% in the first two screenfuls per 2018 NN/g data), not a hard cutoff at one fixed height across all devices. Designing to a single "fold pixel" number ignores that viewport heights vary enormously across devices.

## Open questions

- **Bento grid ROI numbers are unverifiable.** The "+47% dwell time / +38% CTR / +23% task completion" figures are repeated across dozens of 2026 design blogs but every path traces back to an uncredited claim with no published study, sample size, or methodology (confirmed by direct fetch of the originating article). Recommend flagging this in any deliverable as "commonly cited but unverified" rather than presenting it as evidence.
- **F-pattern vs. Z-pattern is not an apples-to-apples research comparison.** The F-pattern is grounded in a real 232-user NN/g eyetracking study (reconfirmed 11 years later). The Z-pattern is an industry-derived heuristic repeated across marketing/design blogs (Instapage, Wordstream, 99designs) without an equivalent eyetracking citation. Both are useful, but they carry different evidence weights — treat F-pattern as [LAW] and Z-pattern as a well-established [MIXED] heuristic.
- **Above-the-fold viewing-time percentage has already shifted once (80% → 57%) and may shift again.** NN/g's own numbers changed between the 2010 and 2018 studies as design norms (longer scrolling pages, mobile-first) evolved. Any specific percentage cited today should be treated as directional, not a permanent constant, and re-checked against NN/g's newer research if this file is revisited after 2026.
- **No source in this research set gives a specific, validated whitespace-to-content ratio for "premium" perception.** Multiple sources assert that more whitespace signals luxury (Apple/Chanel), and one Medium source's "increases perceived value by up to 300%" figure could not be traced to a primary study during this pass — treat as a qualitative direction ("more than a standard content-dense ecommerce page"), not a numeric target.
- **The 44px vs. 48px touch-target discrepancy between Apple HIG and Material Design is real and unresolved industry-wide.** For a web sales site reaching both iOS and Android users, the safer operational floor is 48px (satisfies both HIG and Material simultaneously), but this file's sources don't settle which one a cross-platform web team should standardize on — worth a explicit decision in the skill rather than leaving both numbers to compete.
- **Conversion-lift figures for above-the-fold CTA placement (17%) and social proof (12%) come from a single landing-page-statistics aggregator source and could not be cross-verified against a primary study in this pass.** Treat as plausible/directional rather than load-bearing numbers.
